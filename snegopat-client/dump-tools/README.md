# Дампы vtable платформы 1С: снять и сверить

Эта папка лежит в сборке Снегопата рядом с `x64\`. Зачем она: на новой версии платформы 1С виртуальные методы её интерфейсов могут сдвинуться, и описания в `x64\modules\snegopat\v8api\*.v` перестают попадать в нужную функцию. Дамп `*.vtable` фиксирует, какой слот чему соответствует. Сверка дампов рабочей и новой платформы показывает, куда сдвинулись методы.

Всё делается на одном компьютере, руками. Агент, хаб и сеть не нужны.

## Что нужно

- Windows, 64-битная платформа 1С:Предприятие 8.3. Для сверки две версии: рабочая и новая (две установки на одной машине подойдут).
- Python 3.10+ и два пакета: `pip install capstone pefile`.
- Скрипты из этой папки: `vtcmp.py` (сверка), `v8re.py` и `vtalign.py` (нужны ему как библиотеки; запускать их отдельно не надо).

## Папка под эту сборку

Сборку держите в **отдельной папке**, не смешивая с другим Снегопатом: у неё свои настройки, журналы и дампы, а два Снегопата в одной папке портят файлы друг друга. Путь без пробелов и кириллицы, с правом записи для вашей учётной записи. Распакуйте zip так, чтобы получилось:

```
C:\Snegopat-dumps\snegopat-client\
  README.txt
  x64\                         ← сам Снегопат (x64\starter.exe)
  dump-tools\                  ← эта папка
    README.md  vtcmp.py  v8re.py  vtalign.py
    dumps\                     ← создайте: сюда кладёте *.vtable
      8.3.17.1549\             ← рабочая платформа
      8.3.27.1859\             ← новая платформа
    dll\                       ← создайте, если не хотите указывать каталоги платформ напрямую
      8.3.17.1549\             ← копия каталога bin платформы
      8.3.27.1859\
```

Названия папок версий — ваши, подставьте свои номера платформ.

## 1. Запустить Снегопат

1. Закройте все Конфигураторы. Остановите любой другой работающий `starter.exe` (в Диспетчере задач): два стартёра одновременно внедряются дважды.
2. Запустите `C:\Snegopat-dumps\snegopat-client\x64\starter.exe`.
3. Откройте Конфигуратор обычным способом: Снегопат загрузится, окно сообщений без ошибок.

Закончив, остановите `starter.exe` в Диспетчере задач (иначе он остаётся в памяти до выхода из Windows).

## 2. Снять дампы на рабочей платформе

1. Конфигураторы закрыты, `starter.exe` запущен.
2. Очистите (или переименуйте) папку `x64\dump`, если она есть: иначе файлы разных платформ перемешаются.
3. Для интерфейсов `IInfoBase` и `IConfigMngr` создайте до запуска пустой файл `x64\logs\vt.on`.
4. Запустите Конфигуратор с ключом трассировки Core.As:

```
"C:\Program Files\1cv8\8.3.17.1549\bin\1cv8.exe" DESIGNER /IBName"ИмяБазы" -coreas-tracefunctions 1
```

Ключ ставьте **после** `DESIGNER`: в начале строки платформа его не примет («Неопределен режим запуска»). Единицу не заключайте в кавычки.
5. Дождитесь полной загрузки и закройте Конфигуратор штатно.
6. Скопируйте `*.vtable` из `x64\dump\Snegopat\1cv8.exe\<версия>\x64\` в `dump-tools\dumps\8.3.17.1549\`. Если такой папки нет, поищите `dump` рядом: путь задаёт строка `dumpDir` в `x64\options.ini` (по умолчанию `dump`).

## 3. То же на новой платформе

Тем же `starter.exe`, но запускается `1cv8.exe` новой версии (ключ тот же). Перед этим снова очистите `x64\dump`. Дампы кладите в `dump-tools\dumps\8.3.27.1859\`.

## 4. Сверить

Скопируйте каталог `bin` каждой платформы в `dump-tools\dll\<версия>\` (или укажите `C:\Program Files\1cv8\<версия>\bin` напрямую). В папке `dump-tools`:

```
python vtcmp.py --old dumps\8.3.17.1549 --new dumps\8.3.27.1859 ^
    --old-bin dll\8.3.17.1549 --new-bin dll\8.3.27.1859
```

Только нужные интерфейсы: добавьте `--only IInfoBase IConfigMngr`. Для каждого интерфейса, который есть в обоих наборах, печатается соответствие «объявленный метод старой версии → слот новой» (`?` — не нашлось), число слотов в блоках совпадения и модуль, в котором лежит vtable.

## 5. Как читать результат

| Результат | Что значит | Что делать |
|---|---|---|
| все слоты совпали | `.v` годится для новой платформы | ничего |
| сдвиг на k слотов, начиная с какого-то номера | в новой версии добавили или убрали метод выше | в `.v` добавить ветку `#elif ver >= …` с другим числом пропусков; старые ветки не затирать |
| `?` у части слотов | функция переписана, отпечаток не совпал | искать смыслом: дизассемблер функции в DLL платформы |
| другой модуль в строке «Vtable in» | интерфейс переехал в другую DLL | прямое сопоставление не работает, ищите по GUID интерфейса в DLL платформы |
| расхождений нет, но падает | слот верный, неверны параметры или раскладка структур | журнал `x64\logs\script-log.txt` и трасса Core.As перед падением |

`.v`-описания лежат в `x64\modules\snegopat\v8api\`. При обновлении сборки папка `x64` заменяется целиком, поэтому свои правки `.v` храните отдельно (в своём репозитории или копии).

## Что нужно знать об ограничениях

- В дампах x64 нет дизассемблера и проверки числа параметров функции. Код функций `vtcmp.py` читает сам из DLL платформы по смещениям из дампа.
- Параметр `--agent` у `vtcmp.py` в этой сборке недоступен: DLL новой платформы положите в `--new-bin` сами.

## Если не работает

- `starter.exe` падает с `0xC06D007E`: распакуйте zip заново целиком (в сборке должна быть папка `x64\lib\x86`).
- Дампов нет: проверьте, что Конфигуратор запущен с ключом и что `starter.exe` был запущен **до** него; смотрите `x64\logs\` (`script-log.txt`, `script-errors.txt`).
- Снегопат не загрузился в Конфигуратор: проверьте, что в строке запуска нет `/DisableSnegopat` и что не задана переменная окружения `NOSNEGOPAT`.
- При обращении за помощью приложите папку `x64\logs`, версии платформ и точную команду запуска.
