# Перенос Снегопата на новую версию платформы: методика диагностики

Движок Снегопата привязан к внутренним раскладкам платформы 1С (слоты vtable COM-интерфейсов,
смещения полей, размеры структур). Перенос на новую версию — это снятие фактических раскладок,
их сверка со старой и добавление версионных веток в `v8api/*.v`. Здесь собраны инструменты
диагностики, встроенные в движок; инструмент командной строки — в `dump-tools/README.md`.

## 1. Диагностика: logs/diag.ini (diag.as)

Файл `x64/logs/diag.ini` — строки «ключ=значение» («;» — комментарий), перечитывается не чаще
раза в 2 с, перезапуск 1С не нужен:

- `trace=on` (или `log=on`) — подробный журнал: аргументы перехватчиков, клавиши, потоки,
  дампы vtable (то, что раньше включал файл-флаг `logs/vt.on`);
- `cat.<категория>=on|off` — выборочно по категориям (`list` — подсказка, `colors` — раскраска,
  `keys` — клавиатура, `vt` — vtable, `prof`, `mainmenu`, `main`, `win`, `slow`, …);
- `hook.<имя>=on|off` — принудительно включить/выключить перехват платформы (`list`, `colors`,
  `mainmenu`); без ключа — решение по умолчанию для версии;
- старые флаги-файлы `logs/vt.on`, `logs/nohook-<имя>.on`, `logs/hook-<имя>.on` продолжают работать.

Журнал — `logs/script-log.txt` (UTF-16): «секунды.мс pPID tПОТОК #номер [категория] текст».
Суточная ротация (`script-log-ГГГГ-ММ-ДД.txt`, при >32 МБ ещё и `-N`), хранятся 3 суток.
Последние 300 строк держатся в памяти (`diagTail`) — их отдаёт `snegopat.diagTail()`
(используется `tools/crashinfo.py`). Строки `diagAlways` пишутся всегда, остальные — при трассировке.

## 2. Дампы vtable

**Встроенный дамп `dumpVtable(&&интерфейс, "Имя")`** — пишет `dump/<алиас>.vtable` относительно
корня `x64`: все функции интерфейса, объявленные в `v8api/*.v`, с дизассемблером и проверкой
числа параметров (методика автора). Вызовы расставлены в ключевых местах: `getIBMDCont`
(com_metadata.as — `IInfoBase`, `IConfigMngr`), хуки создания текстовых окон (`main.as`,
включается `#if test = 1` — перекомпилировать с тестовым флагом). Активируется трассировкой
категории `vt` (`trace=on` или `cat.vt=on`).

**Внешние дампы** (нужны для vtcmp/vtalign — сравнения версий между собой):
`logs/vt.on` (или `trace=on`) + запуск Конфигуратора с `-coreas-tracefunctions 1`, копия
`x64/dump/.../*.vtable` в `dumps/<версия>/`. Подробно — `dump-tools/README.md`.

## 3. Проба интерфейсов

`engine/probe_ifaces.as` — `probeIfaces(объект)`: QueryInterface объекта по всем интерфейсам,
описанным в `v8api/*.v` (список генерируется из `.v`); возвращает строку имён поддерживаемых
интерфейсов. Используется формой диагностики, когда надо понять, «что это за объект».

## 4. Пробы слотов

`tools/slotprobe.py` (вставка в код: метка в com_metadata.as около `getIBMDCont`) временно
вставляет вызов пробы слота — быстрый способ проверить гипотезу «в этом слоте лежит такая-то
функция» до внесения изменений в `.v`.

## 5. Сверка версий и правка

1. Снять дампы на рабочей и целевой версиях (§2, `dump-tools/README.md`).
2. `python dump-tools/vtcmp.py --old dumps/<старая> --new dumps/<новая> --old-bin <bin> --new-bin <bin>` — сдвиги слотов.
3. Сомнительные слоты — `vtalign.py` (выравнивание по бинарным дампам), `v8re.py guid` (поиск интерфейса по GUID, если он переехал в другую DLL).
4. Правки — версионными ветками в `v8api/*.v` (`#if (ver >= X & ver < Y)`, старые ветки не затирать),
   специфичные смещения/тайминги — константами в соответствующем `.as` (пример: mainmenu.as).
5. Ослабить/пересмотреть guard в `v8api/process.v`.
6. Добавить версию в `SUPPORTED` в `tests/test_compile.py` и `tests/test_v8api.py`, прогнать тесты.

## 6. Приёмка после переноса

Старт с журналом без ошибок; пункт меню; подсказка (Ctrl+Пробел, «Методы модуля» Ctrl+1);
раскраска запросов и `//{ //}`; панель окон, настройки, справка. Чек-лист — `docs/ISSUES.md` (P3).
