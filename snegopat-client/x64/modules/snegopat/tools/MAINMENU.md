# Пункт меню «Снегопат» в главном меню Конфигуратора: реверс и раскладка

Методика и константы для `engine/mainmenu.as` (пакет `MainMenu`, уровень `piOnFirstIdle`).
Включение: `logs/diag.ini`, `hook.mainmenu=on` (на 8.3.27 и 8.5 включено по умолчанию,
выключить: `hook.mainmenu=off`). Состояние поддержки и известные проблемы — `docs/ISSUES.md` (P0-3).

Платформа не даёт публичного API для добавления пунктов в главное меню, поэтому весь механизм —
работа с внутренними структурами менеджера панелей (перехват vtable + сырые вызовы слотов).

## 1. Как устроено меню платформы

- Команда идентифицируется парой `{GUID группы, номер}` (`CommandID`, 32 байта: 16 байт GUID + dword номера на смещении 0x10).
- Меню — «панель» (band) с содержимым-вектором пунктов. Каждый пункт — запись 0x70 байт, ссылающаяся на CommandID и «вес» (double) для сортировки.
- Главное меню — панель `{B78F2E80-EC68-11D4-9DCF-0050BAE2BC79}/1`. Пункт верхнего уровня («Снегопат») — popup-команда, у которой есть одноимённая панель с подпунктами; здесь это `{A1C0F2E4-…}/1`, а «Настройки Снегопата» — `{A1C0F2E4-…}/2` (листовой пункт).
- Пункт рисуется по «описанию команды» (`ICmdDescription`), которое создаётся при регистрации команды через `ICommandService.registerCommands`; платформенные модули дополняют меню так же: создают `CommandInterface`, кладут в него панели (`addBand`) и отдают менеджеру (`addSource`).

## 2. Используемые сервисы и слоты

| Что | Как достаётся |
|---|---|
| `ICommandService` | `currentProcess().getService(IID_ICommandService)`, `{8F885821-D353-11D3-8A57-008048DA06DF}` |
| слот 11 `ICommandService` | `registerCommands(bundle, массив_записей, количество)` |
| менеджер панелей | `[ICommandService + 0xD0]` (`MM_MANAGER_OFF`) |
| слот 3 менеджера | панель по CommandID (`mmBand`): выходной указатель на 16 байт → `mem::int_ptr[outp]` |
| слот 10 менеджера | `addSource(источник, MM_REBUILD)` — подключить наш источник |
| слот 13 менеджера | перестройка панелей (`MM_SLOT_REBUILD`) |
| слот 4 источника | `addBand({панель}/номер, вектор_пунктов, 0)` |
| слот 13 источника | завершение (`MM_SLOT_FINISH`) |
| `CommandInterface` | `createByClsid({F459D5F0-E7C0-11D4-9DCD-0050BAE2BC79}, {7DF15090-7A63-11D4-84A1-008048DA06DF})` — источник панелей |

Сырые вызовы слотов — `mmCall(fn, a1..a4)`: функтор создаётся на лету через `initFuncDefFromAddress` и кешируется (`mmAddrs`/`mmFns`).

## 4. Раскладка записей

**Пункт панели** (`mmItem`, mainmenu.as:180-191): копия шаблонного пункта живой панели
(образцы берутся `mmTemplate`: у панели вектор `[band+0x30]..[band+0x38]`, первый элемент — образец),
размер копии `MM_ITEM_SIZE = 0x70`. В копии правятся: GUID группы, номер (dword на +0x10),
обнуляются dword-ы 0x14…0x30, на +0x30 — вес (uint64-представление double), 0 на +0x38/+0x3C.

**Вектор пунктов** (`mmVector`): 32 байта — begin/end/capacity, все равны `items + count * 0x70`.

**Запись `registerCommands`** (`mmCmdEntry`, mainmenu.as:201-214), размер `MM_ENTRY_SIZE`:

| Смещение | 8.3.27 / 8.5 | 8.3.17.1549 | Содержимое |
|---|---|---|---|
| +0x00 | GUID | GUID | группа команды (`MM_GROUP`) |
| +0x10 | dword | dword | номер команды |
| +0x14 | GUID | GUID | категория |
| +0x28 | ptr | ptr | bundle (`mmNewAnsi("frame")`) |
| +0x30 | ptr | ptr | имя команды (`mmNewAnsi`, ANSI с нулём) |
| `MM_E_STR` | +0x40 | +0x38 | пустая `v8string` (SSO: 24 байта нулей) |
| `MM_E_INT1` | +0x58 | +0x54 | int `-1` |
| `MM_E_INT2` | +0x5C | +0x58 | int `1` |
| `MM_E_BYTE` | +0x60 | +0x5C | byte `1` |

`MM_ENTRY_SIZE` = 0x68 (8.3.27/8.5) или 0x60 (8.3.17).

**Текст пункта.** На 8.3.27 и 8.5 `v8string` — SSO: текст до 10 символов можно писать прямо в
описание команды (`MM_DESCR_TEXT = true`, `mmSetCommandText`, mainmenu.as:217-232):
база описания `b = d.self - 0x70`, на `b + 0x68` — флаг «строки разрешены» (=1),
текст (`mmSetShort`: UTF-16 + слово `11 - длина` на +0x16 хранилища SSO) — в четыре поля
`b+0x08`, `b+0x20`, `b+0x38`, `b+0x50`. На 8.3.17 `v8string` — stlport (28 байт, иная раскладка):
текст ставится только через `ICommandState.setText` из хука `updateState`.
Полный текст пункта («Снегопат», «Настройки Снегопата») длиннее 10 символов — всегда ставится
через `setText` в `mmUpdateTrap`; короткий текст описания нужен платформе до первого `updateState`.
На 8.5 `commandDescription` для наших команд возвращает `null` — не критично (текст всё равно
ставится через `setText`), шум журнала «нет описания команды» переведён с `diagAlways` на `diag`.

## 5. Разделитель

Образец разделителя ищется в живой панели «Сервис» (`mmBand(manager, {MM_FRAME}/52)`) перебором
элементов вектора: GUID `{9D0A2E40-B978-11D4-84B6-008048DA06DF}` с номером 0
(сравнение двух `int_ptr` с константами `0x11d4b9789d0a2e40` / `0xdf06da488000b684`).
Важно: пункты с нулевой группой `{0}/N` разделителями НЕ являются — у них служебное поле
(комментарий mainmenu.as:388-389; ранняя версия кода ошибочно брала их за разделитель).

## 6. Версионные ветки (mainmenu.as:32-82)

| Параметр | 8.3.17.1549 | 8.3.27 | 8.5+ |
|---|---|---|---|
| `MM_SUPPORTED` | true | true | true (раскладка совпала с 8.3.27, подтверждено live на 8.5.1.1529) |
| `MM_DELAY_MS` | 4000 (сборка таймером: перестройка на первом простое роняла платформу; первая отдельная перестройка не раньше 8 с от старта) | 0 | 0 |
| `MM_REBUILD` (флаг addSource) | 0 | 1 | 1 |
| `MM_DESCR_TEXT` | false (stlport-строка) | true (SSO) | true |
| `MM_ENTRY_SIZE` / `MM_E_*` | 0x60 / 0x54,0x58,0x5C,0x38 | 0x68 / 0x58,0x5C,0x60,0x40 | как 8.3.27 |
| `MM_MANAGER_OFF` | 0xD0 | 0xD0 | 0xD0 |

На прочих версиях `MM_SUPPORTED=false` — меню не добавляется, `initMainMenu` пишет `diagAlways` и выходит.

## 7. Перехваты и обработка команд

- `trMMUpdate` → `ICommandReceiver_updateState` (mainmenu.as:241-267): вызов оригинала; по vtable состояния
  читается слот 3 — `id()` (CommandID); для наших команд: слот 6 — `enable(true)`; если текст не был
  записан в описание (`num == MM_SETTINGS_NUM || !MM_DESCR_TEXT`) — `ICommandState.setText` (приведение
  через `toIUnknown` + явный `AddRef`). Первый `updateState` по popup фиксирует отрисовку (`mmConfirmed`).
- `trMMHas` → `ICommandReceiver_hasHandler` (mainmenu.as:269-277): для CommandID нашей группы сразу
  возвращает 1 (платформа считает, что обработчик есть), иначе — оригинал.
- Выполнение: `transmitCommandTrap` (com_events.as:203) вызывает `mainMenuOnCommand(cmd)`
  (mainmenu.as:290-301) — наши команды на платформу не уходят; `{MM_GROUP}/2` открывает окно
  «Настройки Снегопата» макросом аддина `SnegopatMainScript` («Открыть окно Снегопата») через
  `idleHandlersSingle` + `wakeIdle()` (mainframe.as).

## 8. Перестройки и диагностика

Платформа отбрасывает перестройку, пока достраивает меню (загрузка конфигурации, восстановление
окон), видимого сигнала готовности нет — поэтому `mmScheduleRefresh` (mainmenu.as:327-340)
до 60 раз перестраивает панели: шаг 0 — через `MM_REFRESH_MS` (3000 мс), шаги 1..39 — каждые 2000 мс,
далее каждые 10000 мс; до первого `mmConfirmed`.

Журнал (`logs/script-log.txt`, категория `mainmenu`): «пункт «Снегопат» добавлен в главное меню»,
«пункт нарисован: перестроек N, T мс после добавления», «updateState: команда N» и ошибки
отсутствия сервисов/образцов (`diagAlways`, пишутся всегда).
